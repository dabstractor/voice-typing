## 2. Key design decision — in-process recorder via production wiring, NOT the RecorderHost subprocess

- `RecorderHost` has NO feed_audio IPC (cmds: spawn/set_microphone/prompt/abort/cancel/shutdown);
  feeding WAVs through the real child would require production-code changes out of S1 scope.
- Assert (d) "decodes carry initial_prompt" is deterministic ONLY via the executor factory seam:
  a `RecordingPromptedExecutor(PromptedExecutor)` subclass records `(t, prompt, use_prompt)` per
  `transcribe()` call. Log parsing is strictly worse (set_prompt logs only a word COUNT at DEBUG).
- Precedent: test_feed_audio.py constructs `AudioToTextRecorder(use_microphone=False)` in-process
  via `cfg_to_kwargs` + `_filter_kwargs_to_signature`. Child IPC is separately covered by
  test_recorder_host.py.
- PRD says "lite recorder child" — after the single-mode collapse the same wiring IS the child's
  build path (`_worker_main` → cfg_to_kwargs → augment_kwargs_with_executor). Document this
  interpretation in the test module docstring.

## 3. Assert-specific findings

- (a) Cadence: stabilized partials fire ~every 150 ms (`realtime_processing_pause=0.15`); extends
  type guarded deltas; REVISE cycles are rate-limited to ≥300 ms apart and a suppressed cycle types
  NOTHING — a >500 ms typing gap can be legitimate while partials keep arriving. The cadence assert
  must therefore consult the feedback mirror (FakeFeedback timestamps) to distinguish "decoder
  stalled" from "suppressed/frozen cycle".
- (b) Commit: `commit()` types the guarded final, then the trailing space as a SEPARATE
  `type_text(" ")` call; a differing commit does `press_backspace(len(tail))` first (not
  rate-limited). Exactness assert = reconstruct a simulated screen from timestamped events and
  require screen == committed-so-far after every commit cycle; when a rewind precedes a commit
  retype, require `n == len(tail tracked since last commit)`. Real small.en partial-vs-final
  differences make ≥1 revising commit near-certain across utt_simple+utt_multi+utt_punct; spec a
  bounded retry (feed utt_punct) before failing.
- (d) Prompt timeline: after a sentence-final commit (utt_multi sentences end with '.'), expected
  prompt is `""` (ends-with-terminator). The NON-empty case needs a mid-sentence commit — utt_pause
  first half "I want to test whether this system" (no terminator) commits at the 3 s pause
  (post_speech_silence 0.8 s), so the second half's decodes carry it as prompt. Probe warmup
  records one decode with prompt None at t≈0 — filter it. Cap (≤200 tokens) is unit-tested in
  test_prompt_engine.py; T8 asserts all recorded prompts obey it too.
