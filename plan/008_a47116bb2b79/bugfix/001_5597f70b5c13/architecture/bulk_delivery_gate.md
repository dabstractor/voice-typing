# Bulk delivery — diagnosis, measurement and release gate

## Feasibility and confirmed seams (BUG-002)

1. **Recognizer → child → daemon.** `voice_typing/daemon.py:_build_callbacks`, `_construct`/`build_recorder` select one legacy callback (currently `_PARTIAL_CALLBACK_ATTR` = stabilized) via the common factory. `voice_typing/recorder_host.py:_worker_main`, `_RelayFeedback.update_partial`, `_RelayIds`, `RecorderHost._dispatch`, `relay_identity` own spawn construction, identity stamping, IPC and stale/settled rejection. `VoiceTypingDaemon._on_partial` gates listening; `_bulk_handle_partial`/`_bulk_handle_final` assign `_bulk_next_seq` per generation/utterance before controller ingress. The legacy stream-edit branch must not change. The child feed path stages real audio with microphone off; it is an appropriate private A/B seam. See `external_deps.md` before inferring timing from callback names.
2. **Daemon → single writer.** `voice_typing/bulk_controller.py:BulkController.on_partial/on_final/on_final_dropped/arm`, `_process_next`, `_writer_loop` use a bounded deque/Condition and one in-flight target operation with a receiver-owned 250 ms deadline. Pending partials replace only the same key in place, so a queued partial is not inherently replaced by its final. There is no intentional writer debounce. Distinguish missing/late upstream partials from loss during coalescing, work queued behind an op, and late/missing field visibility; a 57-word backlog is not queue depth. Concrete edge cases to test while changing this path: partial capacity is checked before replacing its own queue slot, actual overflow returns skip the post-lock stop hook, and the pre-submit check currently only checks active after leaving the first condition critical section. Compare session/cancel/stop/epoch behavior before any changes; do not add a second writer, let a timer defer the first useful partial, or let a final erase a pending valid change.
3. **Writer → target.** `voice_typing/bulk_delivery.py` defines `DeliveryTarget`, `AcquireResult`, `ShowResult`, `rendered_equal`. R.1/R.5 require a single atomic edit per visible change, zero identical edits, ownership/caret verification, FIFO barriers, stale/canceled-event rejection, fail-closed/no retry, only in-time `APPLIED` increments revision and confirmed span. Keep `latest_recognized`, accepted final and confirmed span distinct; preserve takeover, no typing fallback, and R.6 recovery. `voice_typing/ime/target.py:ImeTarget.show/finalize` and `voice_typing/pi_editor.py:PiEditorTarget` wrap real route operations; an ACK or daemon `last_confirmed_op` is not field paint. `PiEditorTarget` is reachable via `bulk_target_factory`, not automatically selected by a new user setting in this changeset.
4. **Production GTK parity gap confirmed.** `voice_typing/daemon.py:_build_default_bulk_target` returns a pure `_BulkTargetBundle` with `ImeProcess` + `ImeTarget`. `ImeTarget.acquire` calls `request('acquire')`; `voice_typing/ime/manager.py:ImeProcess.request` returns `None` unless already running. `tests/g5_timing_lab.py:GtkRoute.bulk_target_factory` hides this with a lab-only spawn/activation loop. Route acceptance must exercise the real startup path. On `vt-bulk-arm` outside the daemon lock, start the real process and boundedly pump read-only ping activation (`ime/ime_host.py:handle_line`, `_dispatch`, `_acquire`) before acquire; retain pure construction, epoch/listening guard, bounded teardown including failure, held-seat refusal, and the existing fresh-lifetime takeover subscription. No retries of mutations or IM replacement. The Pi `_CancelOnLeaveTarget` harness reset is not production behavior and does not count as a dictation edit.
