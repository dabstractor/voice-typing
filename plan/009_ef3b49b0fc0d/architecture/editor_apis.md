# Editor API feasibility — evidence and release gates

## Local candidates, not a compatibility claim

Bounded version commands returned upstream Pi `1.7.0`, `pi-bolt` `1.7.0 (Pi-Bolt 1.3.2, linux-x64, JIT off)`, and Neovim `v0.12.6` (LuaJIT). Those are useful candidate pins for qualification; no v1 adapter exists or was run, and installed Bolt must not stand in for an isolated genuine stock fixture if provenance differs. No real service/mic/model was used. `integrations/pi/` and `integrations/neovim/` are proposed shipped locations; `.pi/extensions/voice-editor.ts` and `voice_typing/pi_editor.py` are lab-only.

## Pi and Pi-Bolt

Primary, versioned sources: [Pi extension docs](https://github.com/earendil-works/pi/blob/v1.7.0/packages/coding-agent/docs/extensions.md), [keybindings](https://github.com/earendil-works/pi/blob/v1.7.0/packages/coding-agent/docs/keybindings.md), [InteractiveMode](https://github.com/earendil-works/pi/blob/v1.7.0/packages/coding-agent/src/modes/interactive/interactive-mode.ts), [CustomEditor](https://github.com/earendil-works/pi/blob/v1.7.0/packages/coding-agent/src/modes/interactive/components/custom-editor.ts), [TUI Editor](https://github.com/earendil-works/pi/blob/v1.7.0/packages/tui/src/components/editor.ts), [public MouseRegion component](https://github.com/earendil-works/pi/blob/v1.7.0/packages/tui/src/components/mouse-region.ts), [Pi-Bolt stock runtime and plugins](https://github.com/opensec-git/Pi-Bolt/tree/pi-bolt).

- `ctx.ui.getEditorComponent`/`setEditorComponent` are documented factory composition. Create the base at most once *inside* the app-invoked factory and instrument the same component returned for mounting. The app rewires `onSubmit`/`onChange` after the factory returns, and copies default app handlers. Preserve those chains/properties, normal special handlers and extension composition. The lab ([splice proof](../../008_a47116bb2b79/architecture/pi_seam_proof.md), [G3 Pi row](../../008_a47116bb2b79/architecture/g3_pi_prompt_row.md)) proved a splice/caret route with UTF-16 columns and one change event; its orphan-editor bug came from separately instantiating a factory, and its timed claims/reclaims are not a shipping design. Sticky invalidation on replacement/lifecycle or unsupported factory/mode overrides keeps a stale editor from accepting offers; no race to seize the editor slot from other extensions.
- Check `getLines()` / `getCursor()` on the actual instance. `getExpandedText()` is not an offset coordinate space; use it only as an eligibility signal if useful. Refuse ambiguous paste-marker/revision/mode/selection conditions. Precompute and verify the full predicted text and caret for `insertTextAtCursor()`. Source calls one undo snapshot and normalizes CR and tabs; test/refuse payloads the primitive cannot insert exactly before any mutation. Preserve prefix and suffix, refresh rendering, only then send ACK. Guard own synchronous mutation separately from external edit, callback and submit hooks. A mismatch or uncertainty revokes, never attempts a compensating rewrite.
- `InteractiveMode` registers `app.editor.external` (default `ctrl+g`); `CustomEditor.handleInput` dispatches via the supplied matcher/action, not a fixed chord. Intercept before delegation/matcher action; forward user input unchanged, including remaps, after revocation. Submit, terminal edits/paste/caret movement, component/dialog/session replacement and `session_shutdown` need fail-closed handling even where the eventual buffer/caret equals the starting state. Compare and splice in one synchronous UI turn; don't repeatedly resnapshot eligibility to let an invalidation disappear.
- Bolt documents interpreted extensions on the stock non-JIT build and optional variants for some packages; that is not proof of the public wrapper + chosen Unix-socket runtime on stock. Keep TS and socket dependency surface minimal (candidate `node:net` over XDG); early private-PTY smoke both binaries with stock defaults, including real connect/read/write/timers, mounting, remapped external action, mutation/Undo and lifecycle. No local patches, JIT switch, simulated paste or private app internals as fallback. Unsupported APIs fail closed; record blockers before claiming support.
- Invocation caveat: a slash command typed into the pinned draft changes/submits it, so `/voice-stop` alone is not proof of an actionable native Stop, and a slash-only Start cannot use a nonempty draft. Expose the same editor-local callable actions to a non-shortcut UI control that acts without writing the draft (candidate: visible pointer controls via the public component mouse surface in fullscreen terminal UI; prove on both versions, document conditions), and optional user mappings. Check preservation of other input and controls, and test invocation at a live nonempty insertion point. Desktop/pane focus is never a target selector.

## Neovim

Primary references: [API indexing, `nvim_buf_attach`, `nvim_buf_set_text`, window cursor](https://neovim.io/doc/user/api.html), [Lua scheduling](https://neovim.io/doc/user/lua.html#vim.schedule_wrap()), [libuv pipe](https://neovim.io/doc/user/luvref.html#uv.new_pipe()), [undo blocks](https://neovim.io/doc/user/undo.html#undo-blocks). Cross-checked the installed runtime help for the same APIs.

- Use `vim.uv.new_pipe(false)` (Unix stream), monotonic timers and bounded byte framing; use `vim.schedule`/`vim.schedule_wrap` for editor API calls from libuv. A scheduled event captures a local generation; recheck at execution and keep one compare-and-splice UI turn. Use `nvim_win_get_cursor()` (one-based row, zero-based byte col), `nvim_buf_get_changedtick()`, pinned buffer/window, and zero-width `nvim_buf_set_text()` (zero-based row/byte columns) followed by exact cursor placement and read-back. Never use display column or unicode-character count as the byte offset. Explicit Unicode whitespace/delimiter table or scalar classification must match the PRD across languages; Lua `%s` and JS `\s` cannot be assumed equivalent.
- Change, move-and-return, mode switch and buffer/window detach/replace are invalidation events, not just differences at read-back. Combine documented hooks (`nvim_buf_attach`, relevant mode/window/cursor lifecycle and source-input barriers), with a narrowly scoped self-edit guard and scheduled-callback token check. Refuse excluded or special/read-only/nonmodifiable/selection/unobservable modes. Refuse actions that cannot run while preserving Insert; optional mappings should invoke the local action without leaving its mode. Document an editor-local action route usable without any integration mapping; prove it preserves Insert in the actual UI (an ordinary `:` command that first leaves Insert does not qualify on its own). A public in-editor control calling the Lua action and a mode-preserving optional `<Plug>` entry point are candidates; verify invocation, not only direct calls to the splice function.
- Undo transactions are a separate proof from `nvim_buf_set_text`. Local isolated `nvim --headless -u NONE -i NONE -n` microprobe: with ordinary scratch text `pre post`, use the documented `let &undolevels = &undolevels` boundary before each of two zero-width splices; line changed to `pre one two post`, `undo` restored `pre one post`, then `pre post`. This is a technique to evaluate, **not** Insert-mode acceptance: show real insert session with prior typed changes, sequential scheduled offers and one Undo each; don't join user edits, modify persistent options, force modes or write files. The external editor integration is with its live unsaved normal buffer (no direct access to Pi's temp path, no automated save or handoff).
