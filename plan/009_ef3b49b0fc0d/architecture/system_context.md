## Confirmed seed before capture

- `_load_host` shares the resident recorder, releases `_lock` before `RecorderHost.spawn`, then republishes device/context capability. `_arm` currently clears via `_clear_context_prompt()` just before `set_microphone(True)`. An unconditional clear there would erase a confirmed seed. Make the reservation/arm decision under `_lock` but wait for load and prompt confirmation outside it. Treat the 30-second native cap as a total start deadline; a late worker may leave a safely idle resident host, never re-arm it. Worker cleanup/disarm/prompt-clear belongs to its fenced lifetime, not the next one.
- `RecorderHost.set_prompt()` is fire-and-forget; child drains `('prompt', …)` between `text()` calls and `_prompt_targets` fans to unique executor objects; current `PromptedExecutor.set_prompt()` catches its own failures, so calling it cannot count as confirmation. Add an explicit confirmed path with observable known-applied/known-clear result for both active lanes (one object is normal), an ACK carrying only opaque token/generation and outcome, after installation and before arming. Reuse the child ready/capability evidence and command ordering; idempotent token checks, no exceptions containing seed text. Child ACK waiting on its reader, or the control lock, would wedge both the ACK and unrelated clients.
- `prompt_engine.trim_prompt()` uses a newest-word proxy; `rolling_context_prompt()` cuts at `.?!`. The initial seed must bypass the sentence cut, and the initial trim must genuinely fit the model context budget (word count alone is not a proof on CJK or long joined words; installed faster-whisper `transcribe.py:get_prompt()` clips previous tokens to `max_length // 2 - 1`, with `max_length = 448` in that model implementation; use the warmed model/tokenizer and verify the actual cap rather than copying the 448 constant). Validate the adapter's 4 KiB UTF-8 suffix separately, without splitting codepoints. Treat a timeout/partial update/ambiguous old child as unknown, not `unavailable`. On failure/end clear the prompt, or retire an uncertain host before a future arm. Don't put seed in committed text, spacing, latency, logs, feedback, replies or recovery. After first accepted final only, reuse rolling logic; rejected final may settle the boundary but doesn't consume the seed. Native committed input comes only from the current session's accepted finals, not the live draft or other sessions.

## Control/recorder boundaries

- `_default_control_socket_path()` is `$XDG_RUNTIME_DIR/voice-typing/control.sock` (fail when unset), directory 0700 and socket 0600 (`ControlServer.start`). Existing server uses a thread per connection. Keep old one-shot/persistent ordinary commands and structured failures, with a single connection owner for v1. Proposed `voice_typing/editor_protocol.py` owns codec, lease and serialized socket writer; `voice_typing/editor_session.py` owns reservation/ordered delivery state. Wire field values/names and error meanings are in §4.8.1, not in these internal module names. Separate a 32 KiB byte-bounded strict UTF-8 reader/live writer from the exceptional recovery reply, with no reuse of generic output as fallback. Ensure one writer, deadline on the whole frame (not just each fragment), no waits/joins/writes on daemon control lock or recorder reader; do not echo arbitrary request fragments in reasons.
- `RecorderHost._dispatch` invokes recognition callbacks on its **reader thread** before `_final_evt.set()`. `relay_identity` is meaningful inside the callback only, and currently remains latched through an id-less event because assignment is conditional. Repair the per-event boundary for native use without making ordinary legacy id-less events fail. Drive drain from explicit host arm generation and a current in-flight identity/capture boundary; don't infer it from first final, guessed counter across host respawns, or the last arbitrary partial. `_RelayIds` stamps each arm/utterance and current host already deduplicates many stragglers; native must reject unidentified/stale/duplicate/sentinel finals independently of legacy acceptance, with bounded bookkeeping.
- `VoiceTypingDaemon.run` loops `host.text`, `_text_in_flight`, `_final_pending`, `_utterance_finalized`, `_begin_drain`/`_drain_timeout` are the existing natural-final/stop seams; `_maybe_auto_stop` currently disarms directly, and generic `_request_stop` respects `cfg.asr.graceful_stop`. Native needs its own policy: Stop/idle allows only the in-flight utterance and up to 5 s total ACK settlement after bounded ASR drain; loss revokes immediately, recovery-only for at most that utterance; Cancel aborts without waiting on the reader; startup termination prevents late capture. `_safe_abort` must run off-lock and off-reader. `_handle_dead_host` and `request_shutdown` need native teardown; use existing nonblocking ducking and idle-unload transitions (`d1_ducking_seams.md` in plan 008), no redesign. Recheck reservation on commit/end/mic commands and retain ownership through cleanup/drain. Keep status/stop/quit responsive while the owner starts, blocks on reads/writes, drains or is lost.
- Native `on_final` clean/filter/retain/enqueue precedes all generic backend, recovery, `record_final`/latency and log branches; `_on_partial`/`_touch_speech` may update lifecycle, not output. Inspect recorder relay's direct `_feedback` calls and daemon run/arm/guard paths as well; native bypass means no typing/paste/clipboard/adapter activation, evdev guarding, or transcript feedback even during failure. Sanitized abnormal reason/hint are metadata only. `d2_bulk_delivery_map.md` is prior relay/locking evidence, not an adapter to put back into product.

## Buffer ownership and recovery

The native owner has one FIFO (at most eight eligible finals inclusive of its one in-flight offer, max 4 KiB each), with an unambiguous mark *before* a write attempt. From then on uncertainty survives until the exact verified ACK; only exact duplicate of the last ACK is harmless and must not refresh an offer's deadline. Neither timeouts, malformed frames nor failed writes cause resend. At overflow retain accepted text for recovery subject to its distinct retention cap and revoke, never insert a truncated final. Use a monotonic clock for deadlines: owner ping every 2 s, lease 6 s, whole write 2 s, offer ACK 5 s, capped finishing budget as above. Reader/lease/ACK/worker can race; make revocation sticky before any subsequent offer or arm commit.

`SessionRecovery` is a leaf memory store, with `_fit_text` UTF-8-safe byte clipping, ordinary finals+tail and a cap applied only at close. Reuse pure byte helpers/leaf discipline, not that draft semantics. Proposed `NativeRecovery` is keyed by UUIDv4 and accepted-final identity/offer sequence, is actively bounded including separators, discards verified ACKed text, carries possible-prior-insertion flag for attempted but not verified offers, stores at most two nonempty ended sessions of 1 MiB UTF-8, and does not add partial/seed text. Keep attempted/uncertain metadata safe through truncation and loss; limit *serialized* response to 7 MiB, including escaping and framing. Recovery is one-shot explicit read (`voicectl recover [ID]`, no copy, stdout text only, warnings stderr), non-consuming as the contract directs, entirely separate from `voicectl session [--copy]`. Never automatically replay.
