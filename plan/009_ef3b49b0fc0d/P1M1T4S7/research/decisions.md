# P1.M1.T4.S7 — decisions (design questions found while researching; the PRP follows these)

| # | question | resolution | evidence |
|---|---|---|---|
| 1 | How does `_handle` detect a native connection? T3.S4's note says "branches on `request_kind`". | **First-frame rule:** a connection becomes an owner ONLY if its FIRST decoded frame is a dict with `cmd == "editor-start"`. Never branch on `request_kind()`. | `_REQUEST_SPECS` (`editor_protocol.py:258`) includes `stop` and `cancel`; `request_kind('{"cmd":"stop"}')` → `"stop"`, and `validate_request` would then raise `invalid_request` ("missing id") — a voicectl `stop` would get a native refusal + EOF. PRD B: editor-start is the "first frame"; every post-start frame is scoped to the owner connection. |
| 2 | `starting` with or without `"ok":true`? | Emit exactly `{"event":"starting","id":sid}`. | `_EVENT_SPECS["starting"] = {"event","id"}` (:306); `validate_event` rejects unknown keys; both clients validate with it; T3.S4's handoff prescribes it. PRD table's `{"ok":true,…}` is superseded by the shipped codec (S2 owns the vectors). |
| 3 | Who writes the refusal for a rejected first request? | `write_reject(conn, code)` on the connection thread BEFORE any pump exists. | `editor_protocol.py:518-531` ("T4.S7 calls this"); PRD B: "A failed initial request instead gets `{"ok":false,"error":"<code>"}` and EOF." |
| 4 | What is `write_reject`'s code for each failure? | `validate_request` → `exc.code` (`invalid_request` / `unsupported_version` / `too_large`); `reserve_native` → `res.error` (`busy` / `duplicate_id` / `invalid_request`). | `validate_request` :277-320 precedence; `reserve_native` :3247-3275. |
| 5 | Where does the `listening` frame's `context_seeded` / `context_reason` come from? The pump never sees the `ArmOutcome`. | S7 adds `on_committed: Callable[[ArmOutcome], None] \| None` to `begin_native_start`, called by `_native_start_worker` off-lock once `committed` is True (before it parks on `end_evt`). The session emits `listening` in that callback — no tick delay, and before any final can exist (capture opens only after LISTENING). | `_native_start_worker` :3623-3641 (`committed = out.ok and self._native is r and r.stage is Stage.LISTENING`); `ArmOutcome.context_seeded: bool \| None` :304-320; `start_context`/`_context_reply` :3657-3715 is the reason derivation to mirror (`empty` / `disabled` / `unavailable`; `None` ⇒ False + `unavailable`). |
| 6 | How are offers written given the pump is "the ONLY writer"? T4.S2's contract shows `send_line_capped` directly. | Offers go through `pump.send_event(attempt.event())` between `begin_offer` and `finish_offer(ok)`. `ok` = queued (PumpClosed ⇒ False). A real write failure surfaces as `on_loss(WRITE\|IO)` → `native_lost`, which revokes the queue; "the ACK wins" still holds because an ACK can only arrive after the write. The ACK deadline is stamped at `begin_offer` (mark-before-write; the 2 s write cap sits inside the 5 s budget). | `OwnerPump` docstring :547-551 ("`owner-pump-write` — the ONLY writer"); `OfferQueue` docstring :214-243; system_context "Ensure one writer". |
| 7 | How is `finishing` ordered before drain finals if the loop may be mid-iteration when `native_stop` flips the stage? | Decide stage transitions AND `begin_offer` under ONE `d._lock` hold per step; if DRAINING is observed in the same hold as a pending offer, queue `finishing` first and defer the offer to the next step. `native_stop` sets `_native_offer_evt` under `_lock` right after `begin_drain` (:3464), so the next wake sees it. | PRD B: finishing "ordered before any final accepted during that drain"; `native_stop` :3458-3465. |
| 8 | Where do `applied`/`stop`/`cancel`/`lost` run? Pump callbacks "must not block". | `on_command` (reader thread) performs the S5 contracts directly: `with d._lock: q.ack(obj)` then `d.native_settle_kick()`; `native_stop` / `native_cancel` / `native_lost` with `token=tok`. These are short lock holds with no socket I/O (`pump.shutdown` is a queue put); an ACK-driven end is `stopped`/`idle`, for which S6's desktop warning is not attempted. Wrap defensively: a raise becomes REQUEST loss (`delivery_failed`) by the pump. | `OwnerPump._handle_frame` :743-774; S5 contract :3442-3453; S6 (d): warning only for `disconnected`/`timeout`. |
| 9 | What does `on_loss(cause)` map to? | `d.native_lost(cause.end_reason, cause.value, token=tok)`: EOF/IO/FRAME/WRITE → `disconnected`; LEASE → `timeout`; REQUEST → `delivery_failed`. | `LossCause.end_reason` :425-430; S5 contract; T3.S4 :755-756. |
| 10 | How does the session notice `ended`? | ONLY through S6's daemon-level hook: the `ControlServer` registers `set_native_teardown(self._on_native_ended)` at construction; the hook looks the session up by `state.session_id`, calls `pump.shutdown(state.frame())` (last line then EOF; no-op if lost), sets `session.done`. Never build `ended` elsewhere; never call `pump.shutdown()` from another path. | S6 HANDOFF :585-593; `OwnerPump.shutdown` :645-667. |
| 11 | Register-order race: an end can fire between `reserve_native` and `begin_native_start` (stop-during-start, `quit`, Start-cap) before the pump exists. | Insert the session into `ControlServer._sessions[sid]` BEFORE `begin_native_start`; the hook tolerates a missing session (debug log) — the socket is gone anyway. | `reserve_native` arms the 30 s watchdog immediately (:3271); `request_shutdown` ends sessions synchronously (S6 f). |
| 12 | Session loop wake/latency: `listening` must not wait for a tick; deadlines still need a tick. | `listening` is pushed by `on_committed` (decision 5). The loop waits on `d._native_offer_evt` with a ≤ 0.5 s timeout so `q.check_deadline(now)` + `native_settle_kick()` and the revoked-queue safety net run; a spurious wake is harmless (`begin_offer` → None). | S5 contract :3539-3543; system_context "no waits … on daemon control lock". |
| 13 | Overflow: `enqueue` → REVOKED does NOT set `_native_offer_evt`. Who ends the session? | Session tick: if `q.revoked` while the owner is still live → `d.native_lost("delivery_failed", "overflow", token=tok)`. Task 0 first checks whether S5/S6 already end it (`_native_mic_closed_locked` :3500/:3523 handle a revoked queue only inside the `_disarm` tail / settle step); if so the tick is a never-reached no-op and the test asserts the existing path. | `_native_on_final` :3234-3235 ("Only QUEUED enqueues set the event; REVOKED = recovery-only"); PRD B: "switch once to recovery-only drain with `delivery_failed`". |
| 14 | Generic `cancel` while an owner is live — needs a `_dispatch` branch? | No: `VoiceTypingDaemon.cancel()` :2491 already refuses under a live owner (S4). Task 0 confirms the busy reply shape; no `_dispatch` change expected. | `daemon.py:2491` "P1.M1.T3.S4: cancel is not an owner command". |
| 15 | Which clock/timers does the pump use? | `clock=d._native_clock`, `timers=d._native_timers` (via `getattr` fallbacks for stub daemons) so tests' FakeClock/ManualTimers drive the lease too. | `OwnerPump.__init__(…, clock=time.monotonic, timers=None)` :564; `d._native_clock/_native_timers` :1044-1045. |
| 16 | Connection-thread lifetime after the handoff. | The thread stays inside the session loop until `done`, then `pump.wait(WRITE_CAP_S + 1.0)` (the writer needs ≤ 2 s to flush `ended`), drops the session, and only then returns to `_handle`'s `finally` (the second `conn.close()` is harmless). Close the generic `wfile` BEFORE constructing the pump (no third fd). `ControlServer.stop()` retires live sessions via `terminate_native("shutdown", cause="shutdown", token=tok)` within a 3 s budget. | `OwnerPump._finished` closes `conn` :809-818; `_handle` finally :4449-4456; S6 (f) shutdown ends with no drain. |
| 17 | Seed from `context`? | `seed = _normalize_context(context) or None`; `seed_empty = not seed`. The 4 KiB bound is already enforced by `validate_request` (layer 3). | `_normalize_context` :4197; `start_context` :3690-3694. |
| 18 | Does every outbound line get validated? | Yes — `validate_event(obj)` before `send_event` in the session's one `_send` helper (cheap; catches regressions; `pong` is built by the pump itself). | `validate_event` :322 docstring: "used … by the daemon before encode_line". |
